# 重建指南与环境说明

本目录提供的产物有两种用法：
**A. 直接编译官方开源仓库**（最省事，但有闭源依赖缺口）
**B. 用本目录的反编译 C# + 官方 XAML 重建工程**（能编译，但需要补齐闭源库）

---

## 1. 本次分析所用环境（可复现）

| 组件 | 版本 | 用途 |
|---|---|---|
| Windows | Server 2022 / Win10 x64 | 宿主 |
| .NET SDK | 8.0.426（`dotnet-install.ps1 -Channel 8.0`） | 运行反编译工具与自研取证工具 |
| ILSpy CLI | `ilspycmd 8.2.0.7535`（`dotnet tool install ilspycmd --version 8.2.0.7535 --tool-path D:\tools\ilspy`） | 全量反编译 |
| .NET Framework | 4.8（系统自带） | 目标运行时 |
| Git | 任意 | 取官方源码、做 diff |

> `ilspycmd 8.2` 的目标框架是 `net6.0`，在只有 .NET 8 的机器上需设置
> `DOTNET_ROLL_FORWARD=LatestMajor` 才能运行。9.x 以上版本需要 .NET 9/10 运行时。

### 反编译命令

```powershell
$env:DOTNET_ROLL_FORWARD="LatestMajor"
ilspycmd -p -o .\out --nested-directories ".\Plain Craft Launcher 2测试版破解全部主题+移除更新.exe"
```

### 官方源码

```powershell
# 与二进制版本号完全一致的 tag
Invoke-WebRequest "https://codeload.github.com/Meloong-Git/PCL/zip/refs/tags/2.14.0.0" -OutFile pcl.zip
Expand-Archive pcl.zip -DestinationPath .\upstream
```

## 2. 方案 A：编译官方开源仓库（`Meloong-Git/PCL` tag `2.14.0.0`）

### 2.1 环境

1. **Visual Studio 2022 生成工具**，勾选工作负载：
   - `.NET 桌面开发`（提供 VB 编译器、WPF 的 XAML 编译任务 `PresentationBuildTasks`）
2. **.NET Framework 4.8 Developer Pack**（提供 4.8 引用程序集）
3. NuGet 源可用（nuget.org）

命令行安装（可选）：

```powershell
winget install Microsoft.VisualStudio.2022.BuildTools --override "--quiet --add Microsoft.VisualStudio.Workload.ManagedDesktopBuildTools --add Microsoft.Net.Component.4.8.SDK --add Microsoft.Net.Component.4.8.TargetingPack"
```

### 2.2 依赖清单（需还原的 NuGet 包）

| 包 | 版本 | 备注 |
|---|---|---|
| `Newtonsoft.Json` | 13.0.3 | 样本引用 13.0.0.0 |
| `NAudio` | 1.7.3 | 音乐播放 |
| `CacheCow.Client` | 2.13.1 | 含 `.FileStore` / `.Common` |
| `Imazen.WebP` | 10.0.1 | WebP 解码 |
| `ThrottleDebounce` | 2.0.2 | UI 去抖 |
| `MeloongCore` / `MeloongCore.Wpf` / `PCLCS` | 1.0.0.0 | **闭源，仓库中只有空的 `.gitmodules` 目录** |

### 2.3 已知缺口（必须先解决）

`MeloongCore`、`MeloongCore.Wpf`、`PCLCS` 三个程序集**不在开源仓库里**，`Plain Craft Launcher 2.vbproj` 直接引用它们，
因此**开箱即用地编译会失败**。三条出路：

1. **从官方发行包中取 DLL**：PCL 发行版目录里通常带这些 DLL，直接引用即可（最省事）
2. **反编译官方 DLL 重建同名工程**（ILSpy `-p`），保留命名空间与公共 API
3. **自己实现最小 API 面**（见第 3.3 节，工作量较大但可控）

### 2.4 编译

```powershell
msbuild "Plain Craft Launcher 2.sln" /t:Restore,Build /p:Configuration=Release /p:Platform="Any CPU"
```

产物位于 `Plain Craft Launcher 2\bin\Release\Plain Craft Launcher 2.exe`。

## 3. 方案 B：用本目录的反编译 C# 重建

### 3.1 已有材料

```
源码/CSharp反编译/
├─ Plain Craft Launcher 2测试版破解全部主题+移除更新.csproj   ← ILSpy 生成的工程文件
├─ PCL/           130 个 .cs（核心逻辑，含完整 ModSecret 实现）
├─ PCL/My/        VB 的 My 命名空间模拟（MyWpfExtension / Resources / MySettings）
├─ controls/ pages/  WPF 页面与控件的 C# 代码（含 InitializeComponent 之外的逻辑）
├─ PCL.Resources.resx     4.76 MB（图片、图标、字体的资源清单）
├─ images/        48 PNG + 2 JPG + 1 TTF（已从 .resources 导出）
├─ *.baml         61 个编译后的 XAML
└─ app.ico / app.manifest
源码/官方XAML/    63 个可读 XAML（与二进制同版本，UI 结构一致）
```

### 3.2 关键结论：**不要直接编译 ILSpy 生成的 csproj**

ILSpy 的工程文件只是"能还原出类结构"，它把 XAML 留成 `.baml`，`InitializeComponent()` 也是反编译出来的桩，
因此直接 `dotnet build` 必然失败。正确做法是：

1. 新建 **WPF 应用（.NET Framework 4.8，VB 或 C# 均可）** 工程
2. 把 `源码/官方XAML/**.xaml` 全部加入工程，保留 `x:Class="PCL.XXX"` 与目录结构
3. 把 `源码/CSharp反编译/PCL/**.cs` 加入工程；**删除**每个类里反编译得到的
   `InitializeComponent()` 方法体与 `IComponentConnector.Connect(...)`（这些由 XAML 编译器重新生成）
4. 删除 `PCL/XamlGeneratedNamespace/GeneratedInternalTypeHelper.cs`（XAML 编译器会生成）
5. 把 `PCL.Resources.resx` 与 `images/` 按原相对路径加入工程（`Build Action = Resource / EmbeddedResource`）
6. 补齐第 3.3 节的闭源库

### 3.3 需要补齐的闭源 API 面（`MeloongCore` / `MeloongCore.Wpf` / `PCLCS`）

按调用频次排序，实现这些即可让大部分代码编译通过：

| 类型 | 关键成员 | 说明 |
|---|---|---|
| `Logger` / `BaseLogger` / `LogLevel` / `LogBehavior` / `LogMc` / `LogCrash` | `Info/Warn/Error/Debug`、`Instance`、`MinLevel` | 日志门面，调用点 1000+ |
| `StringExtensions` | `Split/EndsWithF/StartsWithF/Contains/IndexOfF/Between/BeforeLast/AfterLast/ReplaceLineEndings/EnsureLength/GetStableHashCode/Upper/Lower/DeserializeJson/Trim` | 字符串工具，调用点 700+ |
| `FileUtils` | `Exists/Delete/Copy/Move/ReadAsString/Write/TryReadAsString/ReadAsJson/GetInfo/ExtractToDirectory` | 文件封装 |
| `PathUtils` | `AddSlashSuffix/RemoveLastPart/GetLastPart/IsParentOf/IsSame/GetDiskName` | 路径工具 |
| `DirectoryUtils` | `Create/Exists/Delete/GetFiles/GetDirectories` | 目录工具 |
| `EnumerableExtensions` | `Join/Distinct/ToList/Contains` | 集合工具 |
| `ExceptionExtensions` | `GetDisplay(ex, bool)` | 异常美化 |
| `MathUtils` | `Clamp` | 数值 |
| `CryptographyUtils` | `ComputeHash(string, HashMethod)`（**实测 = 小写 MD5 十六进制**）、`EcdsaVerify` | 签名/校验 |
| `RegistryUtils` | `TryRead/TryWrite` | 注册表 |
| `WindowsUtils` | `HasAdminRole` | 权限判定 |
| `StringUtils` / `GeneralUtils` | 杂项 | |
| `OneOf<T1,T2>` | `Is<T>/As<T>/op_Implicit` | 联合类型（`ColorHueTopbarDelta`、土豆码返回值） |
| `Paths` | `Base`、`BaseThenName`、`AppDataThenName` | 路径常量 |
| `MeloongCore.Wpf.MyWpfExtension` | `Computer.Info.AvailablePhysicalMemory`、`Computer.Screen` | VB `My` 命名空间模拟 |

> 其中 `CryptographyUtils.ComputeHash` 的算法本次已通过黑盒验证确定为 **MD5（小写 hex）**，
> 可用于核对实现是否正确（见《02-破解分析》第 2 节第 5 条）。

### 3.4 VB → C# 的语法坑（反编译产物里都能看到）

- `Conversions.ToInteger/ToString/ToBoolean`：VB 的宽松转换，直接用 `Microsoft.VisualBasic.CompilerServices.Conversions`
- `Operators.CompareString(a, b, TextCompare)`：VB 的 `=` 字符串比较，`TextCompare: false` = 区分大小写
- `ProjectData.SetProjectError/ClearProjectError`：VB 的 `On Error` 残留，C# 里可直接删除
- `Information.IsNothing(x)` → `x == null`
- `checked { ... }`：VB 默认开启整数溢出检查
- `_Closure$__36-0`、`_0024VB_0024Local_xxx`：VB 闭包与局部变量名，**不要重命名**（否则与 BAML 里的
  事件处理器名、`x:Name` 对不上）
- `[SpecialName]`、`VB$AnonymousDelegate_*`：VB 委托类型，保留即可

## 4. 验证清单

重建后按以下顺序自检（与样本行为逐条对应）：

1. 启动日志出现 `程序版本：快照版 2.14.0.0 (412)`、`第一阶段/第二阶段/第三阶段加载用时`
2. 设置 → 个性化：主题数量 15（0–14）+ 特殊 42，隐藏主题带锁（**官方行为**）
3. 设置 → 启动器 → 检查更新：能走完 `IsLauncherNewest` 并提示"已是最新/发现更新"
4. 启动一个 Minecraft 实例：`登录 → 获取 Java → 补全文件 → …→ 启动进程` 全链路成功
5. 打开一次崩溃报告：`CrashAnalyzer` 能给出诊断结论
